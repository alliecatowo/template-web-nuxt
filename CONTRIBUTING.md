# Contributing

Thanks for wanting to help. Here is the short version.

1. **Open an issue first.** Describe the bug or idea so we can agree on the approach before you spend time on code.
2. **Keep pull requests small.** One change per PR is easier to review and faster to merge.
3. **Use conventional commits.** For example `fix: handle empty input` or `feat: add dark mode`. PR titles should follow the same style.
4. **Run the project's checks** (tests, lint, type checks) before you push. The repo README says how.
5. **Be kind.** Everyone here follows the [Code of Conduct](CODE_OF_CONDUCT.md).

Found a security problem? Please do not open a public issue. See [SECURITY.md](SECURITY.md).

By contributing, you agree that your contribution is licensed under the same license as the repository.
